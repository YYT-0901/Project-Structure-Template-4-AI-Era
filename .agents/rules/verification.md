# 验证与交付规范

适用范围：功能实现、Bug 修复、重构、配置修改和任务交接。

- 开始时确定可观察的成功条件；多阶段任务在 `.tasks/` 记录步骤及各自的 verify。
- 验证力度与改动风险相称。Bug 修复优先复现问题，再验证修复和关联行为；不要只验证实现本身的字面结构。
- 执行已确定的必要检查。通过后不为制造工作量反复扩大测试范围；有失败或未解疑点时继续定位。
- 记录实际命令、工作目录、环境、结果及证据；失败、跳过和未执行分别说明。
- 重要配置变更验证其加载后的行为；构建成功不能替代业务路径验证，模拟环境不能证明真实服务已连通。
- 交付前核对需求、变更、检查结果和文档一致性；更新相关知识与任务状态。

项目的真实命令在 [.memories/04-development-guide.md](../../.memories/04-development-guide.md) 维护。模板阶段无可执行的应用命令，不能据此声称应用测试通过。

verify：验收条件有对应证据，未完成项有影响说明，最终结论不超出实际验证范围。
