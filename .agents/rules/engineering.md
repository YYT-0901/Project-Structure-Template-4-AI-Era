# 工程变更规范

适用范围：所有代码、配置与架构变更。专项语言规范在选型后补充，并在 `AGENTS.md` 登记。

## 设计与实现

- 先关联需求和验收条件；重大取舍记入 `docs/decisions/`。
- 遵循已确定的框架惯例和目录边界，不另建同用途的平行结构。
- 优先用最小方案解决当前问题，不为假想需求增加抽象、服务或依赖。
- 只修改任务相关内容，匹配已有命名、格式和错误处理方式。
- 外部输入、权限和数据一致性的校验放在明确的职责边界，具体机制根据所选技术补充。
- 依赖新增须有需求用途；确定版本并使用该生态的锁定或校验机制。

## 项目专项大纲

选型后按需补充：语言与格式、模块依赖、接口契约与错误、数据与事务、UI 与国际化、日志与配置。无需全部拆文件；不适用的内容说明原因，不照搬其他项目的实现要求。

verify：检查 diff 是否都能追溯到任务，新增依赖是否有依据，代码是否符合真实目录边界和适用的格式/静态检查。
