# AI 配置的统一来源

| 类型 | 解决的问题 | 位置 |
| --- | --- | --- |
| AGENTS | AI 从哪里开始、读取哪些约束 | 根目录 `AGENTS.md` |
| Rule | 哪些情况下必须遵守什么 | `rules/` |
| Skill | 某类重复任务如何执行 | `skills/<名称>/SKILL.md` |
| MCP | 外部工具的连接、环境和能力边界 | `mcp/` |

规则正文保留在本目录，入口文件只引用；项目知识保留在 `.memories/`，不复制进每个 skill。

## 客户端适配

这是本仓库的组织约定，不假设任何客户端自动发现全部目录。初始化时确定实际使用的 AI 工具，核实其当前官方加载方式，再生成必要的专用入口或配置。没有原生加载时，从 `AGENTS.md` 明确读取；原生配置由单一来源生成，避免多处手改。

## 新增规则

每个 rule 写明适用范围、约束和验证方式；使用真实路径，区分全局与模块规则。在 `AGENTS.md` 登记触发条件。与已有约束冲突时先解决冲突，不以堆叠更多规则掩盖问题。

## 新增技能

只有存在可复用工作流时才新增技能。目录与名称一致，使用小写字母、数字和连字符。`SKILL.md` 至少包含以下元数据和正文；按需增加参考资料或可验证的脚本。

```yaml
---
name: skill-name
description: 说明完成什么任务、何时触发。
---
```

正文覆盖：输入、必要上下文、执行流程、产出、验证方式、无法继续时的处理。具体动作沿用当前用户授权，不因技能存在而自动获得外部操作权限。
