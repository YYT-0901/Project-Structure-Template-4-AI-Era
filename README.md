# Project Structure Template

面向 AI 开发的新项目起点：用需求文档生成技术选型、工程骨架、协作规范、工具配置和项目知识。

本仓库当前处于**模板状态**。它提供通用大纲和生成流程；业务代码、技术栈、运行命令尚未生成。

## 使用方式

1. 将本仓库复制或作为模板创建为新项目。
2. 把原始需求放到 `docs/requirements/`，在 [需求摘要](docs/requirements/project.md) 登记来源和约束。
3. 把 [初始化提示词](docs/prompts/bootstrap.md) 发给 AI，并提供真实需求文档路径。
4. AI 按 [初始化流程](docs/bootstrap.md) 执行，在 [初始化任务](.tasks/initialization.md) 记录进度与验证证据。
5. 验收通过后，按实际产品改写本 README，保留初始化流程供维护参考。

如果需求存在影响技术栈或业务含义的歧义，先明确该项；其他不依赖它的工作继续推进。

## 固定结构

```text
.
├── README.md                   项目入口，初始化后改写为产品说明
├── AGENTS.md                   AI 协作入口与规则路由
├── .agents/
│   ├── README.md               rules / skills / MCP 的职责与加载说明
│   ├── rules/                  可复用工程规范与项目专项规范
│   ├── skills/project-bootstrap/SKILL.md
│   └── mcp/                    连接清单、权限与配置示例
├── .memories/
│   ├── README.md               项目知识索引
│   └── 01-…08-….md             项目概览、架构、开发与业务知识
├── .tasks/                     当前任务、方案、进度与验证记录
└── docs/
    ├── bootstrap.md            初始化阶段、产出与验收
    ├── prompts/bootstrap.md    可直接交给 AI 的初始化指令
    ├── requirements/           原始需求与结构化摘要
    └── decisions/              技术选型与重要设计决策
```

语言、框架、源码目录、测试工具、数据库、部署方式按需求确定。固定的是协作与文档结构；代码组织遵循选定框架的惯例，并记录模块边界，避免每次由模型自由发明。

## 各类内容放在哪里

| 内容 | 维护位置 | 原则 |
| --- | --- | --- |
| 用户要什么、验收什么 | `docs/requirements/` | 保留来源，区分需求和建议 |
| 为什么选择这个方案 | `docs/decisions/` | 记录取舍、状态和适用条件 |
| AI 每次如何开始工作 | `AGENTS.md` | 简短入口，指向详细规范 |
| 必须遵守什么 | `.agents/rules/` | 标明作用范围与验证方式 |
| 某类任务如何完成 | `.agents/skills/` | 明确触发条件、输入和产出 |
| 可以连接什么工具 | `.agents/mcp/` | 声明连接不代表安装成功或获得操作授权 |
| 项目目前是什么样 | `.memories/` | 只把有依据的内容写为事实 |
| 这次做到哪里 | `.tasks/` | 记录当前进度和未完成事项 |

同一规则只维护一份正文；其他文件链接引用。工具专用配置从这些来源适配，并记录加载验证结果。

## 模板填写约定

- `[待补充]`：缺少输入，不得自行补成已确定事实。
- `[待实现]`：已有设计，代码或配置尚未落地。
- `[未验证]`：已经生成，但尚无运行证据。
- `不适用：原因`：确实不需要的能力，不为填满目录引入依赖。

初始化后仍可保留非阻塞待办，但必须列出影响；验收必需项未完成时不能宣布初始化完成。需求和方案支持的内容可以先记录为设计，必须标明状态。

## 完成标准

- 技术选型有需求依据、明确版本和取舍。
- 项目能从干净环境按文档安装、启动、检查与构建；不适用项有解释。
- 最小可运行路径与真实需求有关，且有可观察的结果。
- `AGENTS.md`、rules、skills、MCP 的入口与实际使用工具相符。
- `.memories/` 指向真实文件，区分已实现、设计和待验证内容。
- 初始化任务包含执行命令、结果、未完成事项和需求对应关系。

这些标准约束产出与验证，不能保证不同模型逐字生成相同代码。
